## 1. 项目背景与目标

### 1.1 背景

佳宜幼小衔接是一款面向 5–6 岁幼小衔接儿童的启蒙学习 Web 应用，已包含**数学乐园、拼音天地、英语启蒙**三大模块，并具备基础闯关模式、错题本、连续打卡等功能。

当前使用者为一位 **5 岁、正在上幼儿园大班**的男孩，性格上**偏好游戏化的挑战**。现有应用"闯关 = 连续做题 + 得星星"的形式对他而言游戏感不足，缺乏持续打开和挑战的动力。

### 1.2 目标

在不破坏现有学习内容和数据的前提下，通过**游戏化机制改造**，让孩子获得"角色成长 + 即时反馈 + 奖励积累 + 每日目标 + 限时挑战"的多重驱动力，从而：

- 提高主动学习的频次与时长
- 通过连击、升级、奖励等机制提升专注度
- 把学习成果可视化、可积累，形成长期正反馈

### 1.3 成功指标（验收时参考）

- 孩子愿意每天主动打开应用完成至少一组任务
- 单次使用时长较改造前提升
- 每日任务、限时挑战成为固定使用场景

## 2. 用户画像

| 维度 | 说明 |
|------|------|
| 年龄 | 5 岁，幼儿园大班 |
| 认知水平 | 识字量有限，依赖图片、图标、语音提示；数字与拼音为启蒙阶段 |
| 操作能力 | 以点击为主，需要大按钮、大字号、简单路径 |
| 兴趣偏好 | 喜欢游戏化挑战、收集、升级、即时庆祝反馈 |
| 使用设备 | 家长电脑浏览器为主（Chrome/Safari/微信内置浏览器），需响应式 |
| 使用场景 | 家长陪同或孩子独立使用，单机离线可用 |

**设计原则（对大班儿童）**：
1. 一次只聚焦一个目标，界面层级浅、返回路径清晰
2. 反馈要"即时、大声、夸张"（动效 + 音效 + 文字三合一）
3. 奖励和成长要"看得见、攒得住、用得掉"
4. 所有交互必须同时具备"图标 + 文字"双通道（照顾识字量）
5. 不惩罚失败——答错只记录、不清零等级、不扣已得金币

## 3. 现状分析与改造原则

### 3.1 现有游戏化能力盘点

| 能力 | 现状 |
|------|------|
| 闯关模式 | ✅ 12 关，入门/进阶/挑战三档，顺序解锁 |
| 星星评价 | ✅ 每关 1–3 星，记录最佳成绩与尝试次数 |
| 错题本 | ✅ 自动收录错题，支持重练与清除 |
| 连续打卡 | ✅ 连续天数 streak 统计 |
| 今日统计 | ✅ 今日题数、正确率、累计 |
| 音效反馈 | ✅ 答对/答错/通关音效，可在设置开关 |

### 3.2 差距分析

| 缺失维度 | 现状 | 影响 |
|----------|------|------|
| 角色成长 | 无等级、经验、称号 | 孩子无法感知"自己变强了" |
| 奖励经济 | 星星是静态数字，不可花 | 无积累与消费闭环 |
| 即时反馈 | 仅对/错音效 | 缺少连击等兴奋点 |
| 挑战形式 | 无时间压力 | 缺少紧张感与纪录冲刺 |
| 每日目标 | 无任务引导 | 打开应用无明确目的 |
| 数据保障 | 仅 localStorage | 清缓存即丢失，无备份 |

### 3.3 改造原则

1. **数据兼容优先**：所有新增数据在 `loadAppData` 中与默认值做合并，老用户数据不丢失、不报错
2. **不破坏现有模块**：数学/拼音/英语学习内容与题型全部保留
3. **渐进式改造**：先落地第一梯队（P0），二期再做地图/成就/排行
4. **儿童适龄**：全部新交互遵循第 2 节设计原则

## 5. 详细功能需求（P0）

### 5.1 成长系统（等级 / 经验 / 称号）

#### 5.1.1 功能描述

孩子每次做对题目都会获得经验值（XP），经验积累到一定值自动升级，升级后获得新称号并在首页展示等级徽章与经验进度条。升级时有全屏庆祝动效与音效。

#### 5.1.2 经验获取规则

| 行为 | 获得 XP |
|------|:---:|
| 答对一题（任意模块） | +10 |
| 连击 ≥ 3 时，每答对一题 | +10 + 2 × 连击数（额外部分上限 +10） |
| 通关一关（闯关模式） | +50 |
| 限时挑战：每答对一题 | +10 |
| 完成一个每日任务 | +30 |
| 完成全部每日任务 | 额外 +50 |

#### 5.1.3 升级曲线

- 从 Lv1 开始，初始 0 XP
- 升到下一级所需经验 = `100 + (当前等级 - 1) × 50`
  - Lv1→2：100 XP；Lv2→3：150 XP；Lv3→4：200 XP……
- 升级瞬间：触发升级动效（光效 + 称号展示 + 音效），未溢出的经验保留到下一级

#### 5.1.4 称号体系（随等级解锁，共 7 档）

| 等级区间 | 称号 |
|:---:|------|
| 1–3 | 学习小芽 |
| 4–6 | 闯关新星 |
| 7–9 | 智慧骑士 |
| 10–12 | 数学小博士 |
| 13–15 | 全能挑战家 |
| 16–19 | 学习王者 |
| 20+ | 超级学霸 |

#### 5.1.5 界面要求

- **首页顶部**：新增"角色区"，展示等级数字徽章、当前称号、经验进度条（环形或横条均可）、金币数量
- **升级弹窗**：全屏庆祝，展示新称号 + 经验条推进动画，点击任意处关闭
- **答题页**：底部或顶部持续显示本局经验获得累计（可弱化，避免干扰）

### 5.2 金币与奖励商店

#### 5.2.1 功能描述

孩子通过答题、通关、任务获得金币；金币可在"奖励商店"中消费，兑换主题贴纸、皮肤装扮、以及可打印的**通关证书**，形成"赚—攒—花"的完整闭环。

**奖励闭环（总览）**：

```
学习行为（答题 / 闯关 / 限时挑战 / 每日任务）
   ├─ 即时反馈：连击 + 动效 + 音效
   ├─ 成长反馈：+经验值 → 升级 / 称号
   └─ 经济反馈：+金币 → 消费
         ├─ 贴纸包   → 收集图鉴，集齐一套有额外奖励
         ├─ 主题皮肤 → 换装（英雄战士 / 太空 / 恐龙）
         └─ 通关证书 → 可打印，对接现实奖励
```

> 原则重申：**所有奖励只增不减**——答错不扣金币、不降等级、不没收已得贴纸。

#### 5.2.2 金币获取规则

| 行为 | 获得金币 |
|------|:---:|
| 答对一题 | +1 |
| 连击 ≥ 3 时，每答对一题额外 | +1（每题上限 +5） |
| 闯关通关（按本次星级） | 1星 +5 / 2星 +15 / 3星 +30 |
| 完成一个每日任务 | +10 |
| 完成全部每日任务 | 额外 +20 |
| 集齐一套贴纸（点亮图鉴） | +50 |
| 开包开出重复贴纸（补偿） | +5 / 张 |

> 说明：
> 1. 闯关重复挑战仍按本次星级发放，不限制刷关——孩子愿意反复练是正向行为。
> 2. **金币收支平衡参考**：普通做 10 题约得 12–15 币；完成全部每日任务约得 50 币；3 星通关一关得 30 币。一天正常使用可攒 100–150 币——皮肤（80）约 1 天可得，贴纸包（30）约 20 分钟可得，节奏偏快、成就感密集，适合大班儿童。

#### 5.2.3 商店商品（P0 版本）

| 商品 | 价格 | 效果 |
|------|:---:|------|
| 贴纸包（主题分类，每包开 3 张） | 30 金币 | 分类：英雄战士 / 太空 / 恐龙 / 汽车；开出的贴纸进入"收藏墙"图鉴 |
| 主题皮肤（换色换氛围） | 80 金币 | 英雄战士（红金）/ 太空（深蓝紫）/ 恐龙（绿棕）三选一解锁，全局生效 |
| 通关证书 | 50 金币 | 输入孩子名字，生成一张可下载/打印的"学习小达人"证书图片 |

> 贴纸与皮肤是两个维度：**贴纸是可收集的图鉴藏品**（对应各主题/分类），**皮肤是全局界面换装**（影响配色与氛围），互不冲突。

#### 5.2.4 通关证书

- 入口：奖励商店 → 通关证书
- 流程：输入/确认孩子姓名 → 生成证书（含姓名、等级称号、日期、累计题数）→ 可下载 PNG / 直接打印
- 定位：证书用于家长把学习成果变成**现实奖励**（如"集满 100 金币请爸爸兑现一次愿望"），证书由家长打印或存档
- 说明：证书生成基于浏览器 Canvas 渲染，不依赖后端

#### 5.2.5 界面要求

- 新增页面 `/shop`，入口放在首页快捷功能区与角色区金币图标旁
- 商品卡片：图标 + 名称 + 价格 + 已拥有状态；金币不足时置灰并有"还差 X 金币"提示
- 购买成功：短暂庆祝动效 + 音效
- 新增页面 `/collection`（收藏墙）：按主题分类展示贴纸图鉴，显示每套收集进度（如 3/6），整套点亮有额外奖励提示

---

#### 5.2.6 贴纸收集机制

- **开包规则**：30 金币购买 1 包 → 从该套 6 张中随机开出 3 张（不重复）
- **重复补偿**：若开出已拥有的贴纸，自动转化为 **+5 金币**补偿，避免挫败感
- **集齐奖励**：某一套 6 张全部收集 → 收藏墙整套点亮 + 一次性 **+50 金币**奖励
- **展示**：收藏墙按"英雄战士 / 太空 / 恐龙 / 汽车"分栏展示；首页角色区可展示最近获得的 1 张贴纸
- **目的**：把"买买买"变成"集齐一套"的长期目标，同时支持孩子自由选择喜欢的分支（如只集汽车）

### 5.3 连击反馈（Combo）

#### 5.3.1 功能描述

在答题过程中，连续答对累计连击数并实时展示；答错清零。连击带来经验/金币加成与更强的播报，制造"别打断它"的专注动力。

#### 5.3.2 规则

| 连击数 | 展示与播报 | 加成 |
|:---:|------|:---:|
| 1–2 | 无（正常答题） | — |
| 3–5 | "太棒了！3 连击！" | XP +2×连击 / 金币 +1 |
| 6–9 | "超厉害！6 连击！" | XP +2×连击 / 金币 +1 |
| 10+ | "无敌啦！10 连击！" | XP +2×连击 / 金币 +1（金币额外上限 +5） |

- 连击数值在答题区域醒目位置显示，数字随连击数放大抖动
- 答错：连击清零，显示"连击断了"的弱化提示（不惩罚、不扣币）
- 历史最高连击（maxCombo）永久记录，在个人中心/统计中展示

#### 5.3.3 适用范围

- 数学乐园、拼音练习、英语练习、闯关模式、限时挑战中均生效
- 跨页面**不累计**，进入新一局重新计数

### 5.4 限时挑战（60 秒速算）

#### 5.4.1 功能描述

新增"限时挑战"模式：60 秒内尽可能多做对速算题，答对自动出下一题，计时结束展示成绩并记录最好纪录，破纪录有庆祝。

#### 5.4.2 规则

- 题型选择：开始前选择 **10 以内 / 20 以内 / 混合**（默认 10 以内；20 以内建议解锁条件为通关 2 个进阶关，可配置）
- 倒计时 60 秒，环形进度展示
- 每题答对 +10 XP +1 金币，自动进入下一题；答错记录错题本并自动进入下一题
- 结束后展示：**答对题数 / 最高连击 / 本局得分**，并与历史最好成绩比较，破纪录触发庆祝动效
- 最好成绩按题型分别保存（bestTimeAttack: 10/20/mixed）

#### 5.4.3 界面要求

- 新增页面 `/time-attack`，首页快捷功能增加入口
- 开始页：模式选择 + 规则一句话说明（"60 秒能答对几题？"）
- 进行页：倒计时环 + 连击 + 答题卡片（复用现有 QuestionCard）
- 结算页：成绩卡 + "再来一局" + 返回

### 5.5 每日任务

#### 5.5.1 功能描述

每天生成 3 个学习任务，首页展示进度；完成任务领金币和经验，全部完成额外大奖。任务每日按日期重置。

#### 5.5.2 任务池（每天随机抽 3 个，可配置轮换）

| 任务 ID | 内容 | 目标值 | 奖励 |
|------|------|:---:|:---:|
| doQuestions | 做对 10 道题 | 10 | +10 币 / +30 XP |
| combo5 | 连续答对 5 题 | 1 | +10 币 / +30 XP |
| clearLevel | 闯过 1 个关卡 | 1 | +10 币 / +30 XP |
| timeAttack | 完成 1 次限时挑战 | 1 | +10 币 / +30 XP |
| accuracy80 | 单次练习正确率 ≥ 80%（≥10 题） | 1 | +10 币 / +30 XP |

- 全部完成额外奖励：+20 币 / +50 XP，并播放"今日任务全达成"庆祝

#### 5.5.3 重置规则

- 以日期字符串（复用现有 `getTodayDateString`）判断；跨天自动生成新任务并清零进度
- 已完成并领取的任务不可重复领取

#### 5.5.4 界面要求

- **首页**新增"今日任务"卡片：3 个任务条目，每条含图标、描述、进度条（如 6/10）、"领取"按钮；全部完成显示大奖横幅
- 领取奖励即时到账（金币 + XP），到账后有短促动效

### 5.6 备份 / 恢复

#### 5.6.1 功能描述

设置页提供数据导出与导入，防止"清浏览器缓存导致数据丢失"，支持跨设备迁移。

#### 5.6.2 规则

- **导出**：一键将全部数据（设置、进度、错题本、闯关记录、金币、等级、任务等）导出为 JSON 文件下载
- **恢复**：选择 JSON 文件导入，覆盖当前数据；导入前弹出二次确认
- 文件格式：`joye-preschool-backup-YYYY-MM-DD.json`；导出内容即为 localStorage 中 `joye_preschool_data` 的完整快照
- 导入后校验 JSON 结构合法性，失败则提示且不改变现有数据

#### 5.6.3 界面要求

- 设置页新增"数据管理"分组：导出备份按钮、恢复备份按钮、数据说明文案（解释"数据保存在本机浏览器，清除缓存会丢失，建议定期备份"）

### 6.2 新增数据结构（TypeScript 示意）

```ts
// 成长系统
interface GrowthState {
  xp: number            // 当前经验
  level: number         // 当前等级（从 1 开始）
  title: string         // 当前称号（按等级计算，可派生）
  maxCombo: number      // 历史最高连击
}

// 限时挑战纪录：key = 题型（'10' | '20' | 'mixed'）
type TimeAttackBest = Record<string, number>

// 每日任务
interface DailyQuest {
  id: string
  type: 'doQuestions' | 'combo5' | 'clearLevel' | 'timeAttack' | 'accuracy80'
  target: number
  progress: number
  rewardCoins: number
  rewardXp: number
  completed: boolean
  claimed: boolean
}
interface DailyQuestState {
  date: string              // 任务所属日期 YYYY-MM-DD
  quests: DailyQuest[]
  allClaimed: boolean       // 今日全部完成并已领取额外大奖
}

// 贴纸库定义（静态配置，见 src/data/stickers.ts）
interface StickerPack {
  id: 'hero' | 'space' | 'dino' | 'car'   // 分类
  name: string
  stickers: { id: string; name: string }[]  // 每套 6 张
}

// 商店与收藏
interface ShopState {
  ownedStickers: Record<string, string[]>  // packId -> 已拥有贴纸 id[]
  ownedSkins: string[]                     // 已拥有皮肤 id（'hero' | 'space' | 'dino'）
  activeSkin: string                       // 当前生效皮肤（'' = 默认马卡龙）
  certificateCount: number                 // 已生成证书次数
}

// 游戏化总字段
interface Gamification {
  growth: GrowthState
  coins: number
  timeAttackBest: TimeAttackBest
  dailyQuests: DailyQuestState
  shop: ShopState
}
```
